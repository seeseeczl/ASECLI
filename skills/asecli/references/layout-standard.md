# ASE 节点图精排规范

## 目标

ASE 节点图必须呈现出“经过人工精心排列”的秩序感：严格对齐、层层递进、重复结构一致、留白与走线通道清楚。目标不是机械追求零交叉，而是在不改变 Shader 语义的前提下，让读者一眼看出数据从哪里来、经过哪些阶段、最终去向哪里。

## 优先级

发生取舍时按以下顺序判断：

1. Shader 参数、端口连接、计算顺序和最终效果正确。
2. 主数据流从左向右逐阶段递进，Master Output 位于最右侧。
3. 同阶段严格列对齐，主链水平对齐，重复分支使用同一排版模板。
4. 关键线路径短、简洁、可追踪，不穿过无关节点。
5. 组内紧凑、组间留白清楚，Comment 组不重叠。
6. 在满足以上条件后，再减少线与线的交叉和画布占用。

不要为了“零交叉”破坏清晰的递进关系，也不要为了压缩面积把节点挤成蜘蛛网。

## 列、行与递进

- 精排模式以最终 Master/Output 为根，从右向左递归展开上游。一个节点的直属来源按目标 `in_port` 顺序形成兄弟子树带；先计算每棵子树的完整高度，再使子树带中心对齐父节点的输入端口组中心。三级及更深层级重复同一规则。
- 节点被多个消费者复用时只选择一个主父级，选择顺序为：距 Output 的主路径、相同 Comment 归属、现有垂直距离、端口和节点 ID。其余连接是次级边，只参与线路审计，不复制节点，也不破坏主树端口顺序。
- 精排必须使用 Editor 返回的真实节点矩形、标题栏和端口锚点；缩放后的端口/标题坐标必须依据 `GlobalPosition / TruePosition` 还原到图坐标。多 Pass 中无连接的零尺寸 Master 是休眠占位，保持原位且不参与排版；带连接的零尺寸节点或任一已连接端口缺少几何时失败关闭。离线固定尺寸只能用于 `legacy`，不得标记为精排成功。
- 普通兄弟子树垂直间距至少 `32px`；不同 Comment/语义模块间至少 `96px`；父子节点边界水平距离默认 `96px`，必须处于 `64–160px` 范围。
- 先按语义把计算拆成输入、采样、变换、混合、修正、输出等阶段；同一阶段的节点使用完全相同的 x 坐标。
- 相邻阶段使用稳定的水平间距。主路径不得出现无语义原因的左右折返；每条普通数据边都应从左侧阶段进入右侧阶段。
- 主计算链尽量形成一条水平主干。辅助参数、常量和支线靠近其消费者，按端口关系放在主干上方或下方，不把主干挤成蛇形。
- 同列多节点使用稳定的垂直间距，并围绕该模块的视觉中心排列。不要只做到“大致对齐”。
- 两条或更多重复分支必须复用相同的列坐标、阶段间距、节点顺序和行距，形成可直接横向或纵向比较的模板。
- 简单图保留单一水平主干即可，不为了形式强行加组；复杂图再按语义模块分块。

## Comment 组与留白

- 精排完成后按最内层到最外层重算 Comment：左右和底部各 `30px`，顶部标题安全区 `48px`。该内边距同时保证子 Comment 距父框左右/底部至少 `24px`、顶部至少 `40px`。
- 单层 Comment 空白率目标不超过 `55%`，超过 `65%` 是写入错误。计算时把节点本体以及为 `64px` 水平走线、`32px` 垂直间距保留的必要足迹视为有效占用，固定内边距仍计为空白；先报告离群成员，不允许靠缩框制造成员越界。未连接节点按 Comment 归属组成紧凑辅助带，无归属时进入主图下方辅助带。
- 组内节点保持紧凑网格；不同组之间保留明显大于组内间距的空白通道，使模块边界一眼可见。
- 同层或无父子关系的 Comment 组不得重叠。只有明确的“外层功能、内层因果”父子关系允许完整嵌套，禁止部分交叠或边框穿插。
- 同一行或同一列的并列模块，其 Comment 边框也应对齐；重复模块应使用一致的内边距和外部间距。
- 模块输入放在左侧，最终结果或 `Register Local Var` 放在右侧。移动整个模块时，Comment 与全部成员作为复合单元移动，内部相对排版保持不变。

## 连线原则

- 连线交叉不是绝对禁止。少量线与线可以在节点或组之间的空白通道中交叉，只要交叉集中、路径简洁、来源与去向仍可快速追踪。
- 连线不得穿过起点和终点之外的节点本体，也不得贴着无关节点的端口或标题栏经过而制造归属歧义。
- 优先通过对齐源节点、消费者和模块边界获得自然的短线；不要用大幅绕行换取表面的零交叉。
- 同一结果跨组、长距离或被多个分散消费者复用时，使用一个语义明确的 `Register Local Var` 和各消费组就近的 `Get Local Var` 收敛长线。相邻且只消费一次的关系保持直连。
- 不得为了排版改变 Shader 参数、端口连接、计算顺序，或引入重复计算、重复 Register 和无意义 Local Var。

## Local Var 决策门槛

“同一输出被使用两次以上”只能进入候选清单，不能单独作为注册条件。治理时必须同时记录并判断三个维度：

1. **语义边界**：生产者与消费者是否属于不同算法模块或不同 Comment 组。坐标相隔较远但仍属于同一局部算法，不算跨模块。
2. **走线跨度**：直连是否跨越三个及以上布局阶段、出现明显左右回折，或穿过无关节点、Comment 内容区、标题栏、端口密集区。像素长度本身不是门槛，不能因为“超过 300/700 像素”机械注册。
3. **消费离散度**：是否有两个及以上消费者位于不同算法模块或明显分离的画布区域。同组内相邻双扇出仍是局部直连。

按以下优先级决策：

- **必须使用 Local Var**：结果已经作为模块接口注册，但模块外消费者仍从 Register 或生产者直接拉长线；同一结果进入两个及以上独立消费模块，且至少一条线跨模块或跨长距离；单个远端消费者的直连会穿过无关模块，并且通过重新对齐、移动节点或留通道仍无法变得清晰。
- **保持直连**：消费者都在同一 Comment/局部算法内，连线短且不穿无关节点；单个消费者位于相邻模块且直连清晰；多个消费者虽然形成双扇出，但集中在生产者附近、只跨一到两个阶段。不能为了统一形式把这类局部依赖隐藏成 Get。
- **允许混合**：同一结果的本地相邻消费者可继续直连，模块外或远端消费者使用就近 Get。混合的边界必须是“局部实现”与“模块接口”，不能随机选择。

一旦某结果被定义为模块接口，生产者模块右侧只能有一个语义 Register；每个远端消费模块在输入侧放自己的 Get。禁止 Register 已存在却仍向远端消费者拉长线，也禁止为每个消费者重复 Register。

审计或整理报告必须为每个候选结果给出：来源节点、扇出数量、生产者/消费者所属模块、最大跨阶段数、是否穿越无关区域、最终采用“直连 / Local Var / 混合”的理由。没有这些证据时，不得仅凭连线长度或扇出数量批量改造。

## 执行顺序

1. 找出 Master Output、主数据链和所有双扇出/长线候选；记录来源、消费者、模块归属和跨阶段数。
2. 按语义阶段建立从左到右的列，并先对齐主链。
3. 套用重复分支模板，再把辅助输入贴近消费者排列。
4. 调整行距、列距和组间留白，先尝试用自然直连解决局部双扇出和可移动的长线。
5. 按 Local Var 决策门槛复核剩余候选，只改造真正跨模块、分散或无法通过布局解决的线路；已有 Register 的远端直连必须收口到就近 Get。
6. 检查改造前后消费者端口、数据类型和计算语义完全一致，再减少不必要的线与线交叉。
7. 最后创建或校正 Comment，检查组间不重叠和父子组完整包含。

## 验收边界

离线测试可以证明：

- 同阶段 x 坐标一致；
- 相邻阶段和同列行距遵守给定网格；
- 普通 DAG 数据边从左向右推进；
- 重复分支使用一致列与行距；
- Master 位于最右阶段；
- 布局只修改 x/y，连线与其他字段保持不变；
- Comment 组不重叠，父子组只做完整包含。
- 父节点输入端口组中心与直属子树带中心偏差不超过 `8px`，兄弟端口顺序违规、兄弟子树重叠、节点本体重叠均为零；相同输入连续精排第二次必须移动零个节点。

以下项目必须在真实 ASE 画布的正常阅读缩放下验收：

- 普通节点真实宽高、端口锚点和贝塞尔曲线路径下，连线没有穿过无关节点；
- 允许的交叉位于空白通道，数量克制且能追踪；
- 主链、重复分支、组间留白整体呈现严格对齐和层层递进的“精排感”。

ASE 文本不保存上述全部视觉信息。编辑器或 MCP 不可用时，必须把这些项目标记为未验证，不能用 `parse`、`validate` 或离线坐标估算代替。
