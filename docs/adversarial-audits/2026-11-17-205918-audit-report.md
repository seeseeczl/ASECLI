### [P1] AA-LOGIC-030 — 三个命令忽略 `--editor-backend` — `cli/create_command.py:126`、`cli/commentary_command.py:135`

- **证据等级**：已验证
- **触发条件**：用户执行 `asecli create ... --editor-backend bridge` 或 `asecli comment-group --editor-backend codely`
- **错误行为**：`--editor-backend` 通过 `_add_editor_args` 注册（因此**接受**该参数且不报错），但调用点没有把 `args.editor_backend` 传给下游函数；下游使用其默认值 `"auto"`
- **复现**：
  ```
  create_shader_via_mcp(target, spec, mcp_url=..., instance_token=..., allow_remote_mcp=...)
  measure_node_bounds_via_mcp(args.file, mcp_url=..., ...)
  ↑ 均无 backend 实参
  grep -rn "editor_backend" src/asecli/cli/*.py
  → 仅 commands.py(2) / layout_command.py(2)，create 与 commentary 缺席
  ```
- **影响**：显式后端选择被**静默降级为 auto**。在只装了某一后端的 CI 里，用户指定 `--editor-backend mcp` 仍可能被 `auto` 选中 bridge 并产生与预期不同的执行路径；更糟的是如果 bridge 恰好可用，改动会落到不该操作的后端
- **说明**：`gui-support` 同样未传递，但见 AA-LOGIC-031（其底层根本不支持该参数）
- **最小修复方向**：两处补 `backend=args.editor_backend, codely_port=args.codely_port`
- **关联任务**：AA-OPT-030

### [P1] AA-LOGIC-031 — `gui-support --runtime-probe` 硬编码 MCP — `bridge/gui_provider_detection.py:56`

- **证据等级**：已验证
- **触发条件**：`asecli gui-support <project> --runtime-probe` 在未运行 mcp-for-unity 的环境下执行（如仅装 DSH-Bridge）
- **错误行为**：`probe_native_mzgui_for_assets` 签名里**没有** `backend` 参数，内部直接 `McpClient(...)` + `call_tool("execute_code", ...)`，绕过了 `run_editor_code`
- **复现**：
  ```
  inspect.signature(probe_native_mzgui_for_assets) → 无 backend 参数
  grep -n "McpClient(" src/asecli/bridge/gui_provider_detection.py → 命中
  ```
- **影响**：这是**唯一**仍直接依赖 MCP 的 Editor 调用点。在 Bridge/Codely 环境里该命令必然失败，而 CLI 又接受 `--editor-backend`，形成「参数存在但无效」的误导
- **最小修复方向**：改为走 `run_editor_code`，并在 CLI 层传递后端参数
- **关联任务**：AA-OPT-031

### [P2] AA-DATA-035 — 迟到的成功结果被丢弃 — `bridge_client.py:execute_code` finally

- **证据等级**：已验证
- **触发条件**：探针执行耗时略超客户端 `timeout`
- **错误行为**：客户端抛 `timeout` 后，`finally` 删除自己 `outbox/<id>.json`；但探针**随后**才写入成功响应，于是该响应既不被读取也不被上报，残留在 `outbox/`
- **复现**：

  ```
  客户端 timeout=0.3s，探针 0.35s 后写入 {"result":"LATE-SUCCESS"}
  → 客户端报 timeout；1 秒后 outbox 残留 req_asecli_*.json
  ```

- **影响**：调用方以为操作失败（`AA-OPT-014` 已提示"可能已执行"，但仍无法获知结果）。对 `create`/`recompile` 这类有副作用的命令，用户可能在操作其实成功时重复执行。这与"迟到响应清理"（`AA-OPT-023`）存在张力：清理越彻底，可观测性越差
- **最小修复方向**：超时后做一次**短宽限轮询**（如 2 × POLL_INTERVAL 或 200ms），若恰好读到结果则正常返回；否则保留文件一段时间并在错误 `data` 中给出 `outbox` 文件名供人工核查
- **关联任务**：AA-OPT-035

### [P3] AA-LOGIC-036 — 借用 `"codely"` 分支 — `backend.py:run_editor_code`

- **证据等级**：已验证
- **触发条件**：Bridge 返回结果时
- **错误行为**：`extract_payload(text, "codely")`，用另一后端的分支处理本后端结果
- **影响**：两者当前行为一致（都返回裸串），但耦合是隐式的；若任一后端未来改变返回形态，此处会静默错位
- **最小修复方向**：为 bridge 引入显式分支或统一为 `"raw"` 语义
- **关联任务**：AA-OPT-036

### [P3] AA-LOGIC-037 — 未知后端名无防御 — `editor_result.py:extract_payload`

- **证据等级**：已验证
- **触发条件**：传入非法 backend 名
- **错误行为**：静默落入 MCP 分支
- **复现**：`extract_payload('{"success":true,"data":{"result":"X"}}', "typo") → "X"`
- **影响**：内部契约脆弱；`select_backend` 虽先校验，但该函数是公开可复用的
- **最小修复方向**：未知后端名抛 `ValueError`
- **关联任务**：AA-OPT-037
