## 威胁与失败模型

- 资产：Shader 的 `CustomEditor`、三类 `*Mzgui` 属性、ASEBEGIN 节点序列化、用户在 Inspector/ASE 中看到和修改的 GUI 状态。
- 操作者能力：可升级 ASE、导入/移除 MZGUI、移动 Shader、从旧 ASECLI 版本升级、快速执行“应用并保存”。
- 最贵失败：Shader 在一个环境显示正常，进入另一个环境编辑后产生重复 Attribute、GUI 状态不可见或再次保存丢失。
- 单点事实源风险：fallback 把语义放在 ASE 原生 `m_customAttr`；补丁版原生 MZGUI 把自己的开关状态放在 `m_selectedMzguiAttribs` 和额外尾部。
- provider 风险：fallback 与原生实现现在公开相同全名 `MZGUI.MZGUI`，生命周期切换必须先解决旧 provider，不能只依赖最终 Shader 字符串相同。
- 失败边界：反射成员缺失、Custom Editor 赋值失败、ASE Save 方法缺失/抛错、运行时探测命中非标准安装位置。

## Findings 详情

### [P1] AA-DATA-001 — 为原生 MZGUI authoring 增加跨存储协调 — `asecli_material_gui.authoring.part00.cs.txt:154`

- 证据等级：高置信推断。
- 触发条件：在无 MZGUI 工程中用 fallback EditorWindow 写好 Shader，然后把 Shader 放入当前补丁版原生 MZGUI 工程并继续从 Property 节点的 `MZGUI` 折叠区编辑。
- 错误行为：fallback 把 `FoldoutMzgui`、`TooltipMzgui`、`HelpBoxMzgui` 写进 `m_customAttr`；真实 MZGUI 的开关 UI 只从 `m_selectedMzguiAttribs` 初始化，并把选中项写入自己的额外尾部。导入后的 Shader 可以生成相同 ShaderLab Attribute，但原生 MZGUI 面板不会显示这些开关已开启。用户再次在原生面板开启同一项时，Custom Attributes 与 MZGUI 尾部可同时输出同名 Attribute。
- 证据：fallback 的 `Managed`/`TryStorage` 路径位于 `src/asecli/bridge/resources/asecli_material_gui.authoring.part00.cs.txt:154-235`；真实 `PropertyNode.cs:2217-2233,2379-2388,2412-2424,2430-2560` 显示原生 UI/序列化只使用 `m_selectedMzguiAttribs`，而 `m_customAttr` 是另一条输出链。
- 影响：满足“材质 Inspector 能读”的运行兼容，但不满足“进入已有 MZGUI 环境后仍像原生 MZGUI 一样继续编辑”的完整 authoring 兼容；重复 Foldout/Tooltip/HelpBox 的最终行为取决于 Unity/MZGUI 枚举顺序。
- 最小修复方向：明确一个跨 provider 的 canonical authoring 状态；进入原生 MZGUI 环境时通过能力探测做一次幂等协调，确保每个语义只存在于一个存储，不直接猜未知尾部。
- 关联优化任务：AA-OPT-001。

### [P1] AA-COR-001 — 把 Apply 改成预检、提交、失败回滚事务 — `asecli_material_gui.authoring.part00.cs.txt:125`

- 证据等级：已验证。
- 触发条件：Custom Attributes 字段可写，但当前 ASE 版本缺少 `m_customInspectorName` 或 `SaveToDisk(bool)`，或者反射调用保存时抛异常。
- 错误行为：`Apply` 先执行 `TryWrite` 修改节点，再尝试设置 Custom Editor，最后调用保存。后两步失败只显示通知并返回，不恢复已经修改的属性或 Master；`TrySave` 也没有捕获 `TargetInvocationException`。按钮名称“应用并保存”因此可能产生“已应用但未保存”或异常中断的部分状态。
- 影响：用户以后点击 ASE Save 时可能把一次表面失败的操作持久化；属性与 `CustomEditor` 可不一致，正是本次要消除的保存丢失/双 GUI 风险。
- 最小修复方向：写入前预检全部必要成员；快照属性、计数和 Master Editor；统一事务提交；任一步失败恢复快照并报告明确阶段。
- 关联优化任务：AA-OPT-002。

### [P2] AA-COMPAT-001 — 在 Editor authoring 层迁移旧 ASECLI Attribute — `asecli_material_gui.authoring.part00.cs.txt:154`

- 证据等级：已验证。
- 触发条件：升级一个仍含 `ASECLIFoldout`、`ASECLITooltip` 或 `ASECLIHelpBox` 的旧 Shader，然后用新的 MZGUI Attributes 窗口编辑。
- 错误行为：EditorWindow 的 `Managed` 正则只识别三种 `*Mzgui` 名称；旧属性不会加载到 Toggle，也不会在写入时删除。用户开启对应项后，新旧属性共存。MaterialGUI 的 `ApplyMetadata` 又同时识别两套名称，并对 Tooltip/HelpBox执行 `AppendLine`，可能显示重复内容。
- 影响：升级路径表面兼容，但 Editor 内编辑会制造重复语义，且无法从可视化窗口看出旧值仍存在。
- 最小修复方向：将旧名纳入 authoring 读取和等价类型集合；写入时按语义删除新旧全部别名，只写 canonical `*Mzgui`。
- 关联优化任务：AA-OPT-003。

### [P2] AA-OPS-001 — 运行时发现任意 fallback 时阻止第二次安装 — `gui_support.py:46`

- 证据等级：已验证。
- 触发条件：Editor 中已经加载实现 `IASECLIFallbackProvider` 的 `MZGUI.MZGUI`，但该实现不在固定目标 `Assets/Editor/ASECLI/ASECLIMaterialGUI.cs`，例如用户移动了文件或通过包提供。
- 错误行为：runtime probe 返回 `type_found=true, fallback=true, detected=false`；`inspect_gui_support` 忽略 `fallback=true`。临时目录复现得到 `provider=missing, would_write=true, target_state=absent`，随后 `--write` 会再创建一个同全名 provider。
- 影响：可能产生重复类型、Unity 类型解析歧义或编译错误；固定路径摘要校验无法保护非标准安装。
- 最小修复方向：把 runtime probe 的 fallback 作为独立 provider 事实；固定目标不存在时返回 `fallback_external`/`unknown` 并停止写入，报告 assembly 与人工处理路径。
- 关联优化任务：AA-OPT-004。

### [P2] AA-OPS-002 — 为安装原生 MZGUI 前提供可恢复的 provider 交接 — `gui_support.py:141`

- 证据等级：高置信推断。
- 触发条件：工程先安装 ASECLI fallback，之后导入或升级到原生 MZGUI。
- 错误行为：两者都声明 `MZGUI.MZGUI`。当前检查能在事后报告 `multiple`，但没有导入前门禁、禁用/卸载 fallback 的原子操作或 Shader 状态协调。若同程序集会直接重复定义；若不同程序集则 Unity 的字符串类名解析存在歧义，且 runtime probe 只返回遍历到的第一个同名类型。
- 影响：工具能够阻止继续写入，却不能保证工程仍可正常编译或保证使用的是原生 provider；“自动适应”在 provider 生命周期变化时中断。
- 最小修复方向：提供显式、可回滚的 `handoff-to-native` 流程：确认原生候选、备份 fallback、协调 Shader authoring 状态、移除/禁用 fallback、刷新并反射确认唯一原生类型；失败恢复备份。
- 关联优化任务：AA-OPT-005。

## 测试与观测缺口

- 缺失主验收：无 MZGUI Editor 中选择 Property→编辑三项→保存→退出→重开。
- 缺失跨环境验收：同一 Shader 从 fallback 工程复制到原生 MZGUI 工程，确认 Inspector、ASE Custom Attributes、原生 MZGUI Toggle、再次保存和再次重开均无重复/丢失。
- 当前两个 bridge E2E 因未配置工程而 skip；新 `MZGUI.MZGUI` wrapper 尚无本轮真实 C# 编译证据。
- 没有记录 provider 类型的 assembly、脚本路径和 marker 分类全量集合；runtime probe 只返回第一个同名类型，不足以诊断歧义。
- Apply 失败只显示短暂 notification，缺少持久 Console 事件、失败阶段和是否回滚字段。

## 残留风险

- 已验证的是字符串协议和 Python 状态机，不是完整 Unity/ASE authoring 行为。
- 原生 MZGUI 的 HelpBox/Tooltip/Foldout 渲染逻辑与 fallback 实现不同；名称和编码一致不能证明视觉、折叠边界和重复 Attribute 处理一致。
- ASE 更新仍可能改变反射成员或保存签名；当前失败关闭可以保护写入，但 Apply 的前半段并非事务。

## 总评

- 结论：阻塞。
- 前置条件：至少完成 AA-OPT-001、AA-OPT-002，并通过 fallback→原生 MZGUI 双环境真实 Editor 回归；AA-OPT-003/004 应在发布前完成，AA-OPT-005 可与真实迁移流程合并验收。
