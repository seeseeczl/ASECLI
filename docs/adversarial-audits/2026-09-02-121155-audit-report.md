## Findings 详情

### [P1] AA-SEC-001 — 将 GUI 资源创建锚定在不可替换的工程目录 — `src/asecli/bridge/gui_support.py:84`

- 证据等级：已验证。
- 触发条件：`gui-support <project> --write` 已通过 `_assert_inside_project()`；另一进程在 `mkdir()` 与 `os.open()` 之间，把空的 `Assets/Editor/ASECLI` 父目录替换为指向工程外可写目录的符号链接。
- 错误行为：`install_gui_support()` 在第 86 行只做一次路径解析，随后第 88 行以普通路径调用 `os.open(..., O_EXCL)`。隔离故障注入中，目标父目录被替换后，工程外文件被成功创建，字节 SHA-256 与打包 GUI 资源一致；后续第 108 行的复查才报路径越界，既未阻止写入也未清理工程外文件。`O_EXCL` 防止覆盖已有同名文件，但不防止在工程外新建文件。
- 影响：拥有工程目录写权限的并发进程可诱导受信任的 CLI 在该用户权限范围内越过 Unity 项目边界创建文件，违反 README 的符号链接失败关闭承诺。此写入命令需要显式 `--write`，但发布后常被 Agent/自动化调用，故为 P1。
- 最小修复方向：从已验证的工程根/`Assets` 目录描述符出发，以 `dir_fd` 和不跟随符号链接的逐级目录打开/创建完成写入；最终文件也必须用 `O_EXCL` 和 no-follow 语义创建，并在失败时只清理可由该文件描述符证明属于本次事务的文件。
- 关联优化任务：AA-OPT-001。

### [P1] AA-REL-001 — 在分发前补齐当前 C# GUI 的真实 Editor 门禁 — `src/asecli/bridge/resources/asecli_material_gui.cs.txt:25`

- 证据等级：已验证。
- 触发条件：发布当前 CR-0010 未提交工作树构建的 artifact。
- 错误行为：本次变更替换了三个 C# decorator 类型，并改变了旧 `FoldoutMzgui`/`TooltipMzgui`/`HelpBoxMzgui` 的读取路径；但当前环境中 `ASECLI_GUI_TEST_PROJECT`、`ASECLI_TUANJIE_PATH`、`ASECLI_UNITY_PATH` 全部未配置。`tests/TEST.md:15-17` 也明确 Python 测试只能验证资源文本和序列化，C# 编译与视觉行为必须经真实 Editor。历史 Unity 2021.3 证据针对的是 CR-0010 前的旧 decorator 资源，不能证明当前资源可编译、可读取旧标记或可交互。
- 影响：Python 绿色和 wheel 安装成功不足以证明试用者导入工程后不会遇到 C# 编译错误、空 Inspector 元数据或旧 Shader 退化。交付协议要求发布前 S0/S1 清零，因此当前不能进入发布阶段。
- 最小修复方向：使用隔离的 Unity/Tuanjie 工程，安装当前 wheel 的资源，分别加载仅含新标记和仅含旧标记的 Shader；记录 C# 编译结果、Inspector 中的 Foldout/Tooltip/HelpBox 行为和版本信息。目标平台/渲染验收按实际分发范围另行补充。
- 关联优化任务：AA-OPT-002。

### [P2] AA-COMPAT-001 — 让旧标记在无 `GetShaderPropertyAttributes` 的 fallback 中仍可读 — `src/asecli/bridge/resources/asecli_material_gui.cs.txt:201`

- 证据等级：高置信推断。
- 触发条件：目标 Editor 有属性数量/名称和 `MaterialPropertyHandler`，但没有 `ShaderUtil.GetShaderPropertyAttributes(Shader, int)`；Shader 仍使用任一旧 MZGUI 属性标记，且工程不再携带旧 MZGUI drawer。
- 错误行为：fallback 仅枚举 `m_DecoratorDrawers` 并接受实现私有 `IASECLIMetadataDecorator` 的对象（第 211-224 行）。当前资源只定义 `ASECLIFoldoutDecorator`、`ASECLITooltipDecorator`、`ASECLIHelpBoxDecorator`（第 25-52 行），没有可承载旧三种属性的 decorator；因此第 272-280 行的旧名称分支在 fallback 中不可达，旧元数据会被忽略。
- 影响：README 宣称旧标记“只读取兼容”，但该兼容性在代码为兼容旧 Editor 保留的 fallback 路径失效。当前没有对应 Editor 的实机复现，故不把它表述为所有支持版本都会失败。
- 最小修复方向：明确支持的 Unity/Tuanjie 版本矩阵；若 fallback 仍属支持范围，使用不依赖旧外部 drawer 的原始属性读取方式，或提供仅用于读取的内部 legacy decorator 映射，并以真实旧 Editor 验证。若不支持，则删除该 fallback 或在 CLI/README 明确失败边界。
- 关联优化任务：AA-OPT-003。

### [P2] AA-DOC-001 — 使 README 的单属性示例可直接执行 — `README.md:180`

- 证据等级：已验证。
- 触发条件：按 README 第 172-182 行执行 `gui-support --write` 后，对尚未设置 ASECLI `CustomEditor` 的 Shader 执行示例中的 `custom-gui --property ... --group ... --write`。
- 错误行为：安装器只写入工程的 C# 文件，不会修改 Shader 的 `CustomEditor`；而 CLI 在 `src/asecli/cli/custom_gui_command.py:76-82` 要求添加元数据前图内 editor 已为 `ASECLI.MaterialGUI.ASECLIMaterialGUI`。隔离复现返回 `CUSTOM_GUI_ERROR`（exit 2），原 Shader 未变。README 第 215 行的后置说明虽指出 editor 必须采用推荐值，但无法修复前面首个复制即失败的命令。
- 影响：新试用者最常走的逐属性流程会在第一处写入停止，且错误发生在已向工程安装资源之后，增加理解和回滚成本。

- 关联优化任务：AA-OPT-004。
