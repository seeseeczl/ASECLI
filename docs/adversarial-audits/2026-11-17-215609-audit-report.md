### [P2] AA-DATA-040 — 探针未实现 `executionState` — 外部组件（DSH-Bridge 探针 v11）

- **证据等级**：已验证
- **触发条件**：ASECLI 调用超时，但探针仍在执行
- **错误行为**：探针 v11 响应字段为
  ```
  backend, diagnostics, elapsedMs, referenceBuildMs, referenceCached,
  referenceCount, result, resultTruncated, warningCount
  ```
  其中**无 `executionState`**。前序审计（第 2 轮 AA-DATA-014 / 优化计划「对外建议」）已提出该项，探针 v11 新增了 `referenceBuildMs`/`referenceCached` 两个性能指标，但未采纳 `executionState`
- **复现**：真机投递 `unity.code.execute`，观察 `data` 键集合，无 `executionState`
- **影响**：ASECLI 侧已用 `GRACE_POLLS` 宽限轮询缓解（AA-OPT-035），但宽限期过后若仍无结果，客户端只能报「已投递，可能已执行」而无法机器判定。对有副作用的 `create`/`recompile`，用户仍可能重复执行
- **归属**：根因在外部探针；ASECLI 侧可继续加强的是**侧信道证据**——检查 `done/` 中是否出现该请求的记录以推断已处理
- **最小修复方向**：ASECLI 在超时错误中附带「是否已在 `done/` 观察到该请求」的判定结果
- **关联任务**：AA-OPT-040

### [P3] AA-SEC-041 — 穿越探针请求滞留 — 外部组件行为观察

- **证据等级**：已验证（该请求非 ASECLI 产生）
- **观察**：`6d2d4d436a8d4843/inbox/req_traversal_probe.json` 内容为
  ```json
  {"id":"../../__dsh_escape_probe", ...}
  ```
  写入于 21:17，至审计时（21:56）仍未被处理
- **ASECLI 侧结论**：`request_id` 由 `uuid.uuid4().hex[:16]` 生成，字符集经 1000 次采样确认为 `[0-9a-f]`，**不含路径分隔符**，无穿越风险
- **全盘搜索**：未发现 `__dsh_escape_probe` 越界写入文件，说明探针侧对 id 有防护
- **影响**：该滞留条目未阻塞后续 ASECLI 请求（实测队列正常），但会永久占用 inbox 一条
- **归属**：Bridge 侧清理策略问题，已记录为对外建议
- **关联任务**：无（ASECLI 侧无动作）

### [P2] AA-LOGIC-043 — 上限归属错误 — `editor_create.py:116`

- **证据等级**：已验证
- **触发条件**：`create --backend editor` 且图 payload 压缩后仍超 50000 字符
- **错误行为**：抛 `ValueError("compressed Editor create request exceeds MCP's 50000-character limit")`
  - 该上限是 **MCP `execute_code` 的约束**，但 `build_executor_code` 是与后端无关的通用函数
  - 结论：Bridge（文件邮箱）与 Codely（TCP 64MiB 帧）**没有此限制**，却同样被拒
- **复现**：
  ```
  payload 含 120000 字符随机串（gzip 无效）→
  ValueError: compressed Editor create request exceeds MCP's 50000-character limit
  ```
- **影响**：在 Bridge/Codely 后端下，本可成功的大图创建被一条无关的 MCP 限制挡下；且错误消息误导用户排查 MCP 服务器
- **最小修复方向**：把限制标注为 `mcp` 专属；非 MCP 后端放宽或跳过该检查，或至少给出准确措辞
- **关联任务**：AA-OPT-043

### 本轮排除

| 假设 | 结论 |
| --- | --- |
| 双后端执行结果不一致 | 排除，`bridge` 与 `codely` 对同一代码均返回 `consistency-42` |
