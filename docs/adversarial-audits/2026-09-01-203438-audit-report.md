## Findings 详情

### [P1] AA-REL-001 — 在远端双构建一致前阻止 artifact 交付 — `.github/workflows/ci.yml:33`

- 证据等级：已验证。
- 触发条件：GitHub Actions 在同一 `package` job 中以固定 `SOURCE_DATE_EPOCH=1788220800` 连续执行两次 `uv build`，随后比较两个 sdist。
- 错误行为：run `33507715846` 的 Python 3.10/3.12 `verify` 均成功，wheel 也逐字节一致；sdist 比较失败：`build-a/asecli-0.1.0.tar.gz build-b/asecli-0.1.0.tar.gz differ: byte 12, line 1`。SHA256SUMS、SPDX、供应链结果、隔离安装和 artifact 上传全部被跳过。
- 反证边界：当前 macOS 本地以相同 `SOURCE_DATE_EPOCH` 双构建可复现，wheel SHA-256 均为 `4c39fa04...f920`，sdist 均为 `2978d3af...4b2d`；因此远端失败是真实的，但环境相关根因尚未定位，不能把本地成功当成远端恢复。
- 影响：交付协议要求的可下载 wheel/sdist/hash/SBOM/供应链证据不存在，`acb74a0` 不能进入远程 released 或作为已验证远端 artifact 分发。
- 最小修复方向：保留门禁，先采集两个 sdist 的解压清单、成员元数据和 gzip/tar 差异，定位非确定字段；在同一 Linux runner 上证明双构建一致并完成后续上传，不得删除 `cmp` 来换取绿灯。
- 关联优化任务：AA-OPT-001。

### [P1] AA-DATA-001 — 未知 ASE 图版本必须失败关闭而不是沿用未来字段 — `src/asecli/core/custom_gui.py:35`

- 证据等级：已验证。
- 触发条件：图版本为未建档的数值版本（动态用 `25000` 复现），Master 字段 9 已具有未来语义，Property 末尾恰好存在数字 `0`。
- 错误行为：`main_master_node()` 仅判断版本 `>2404` 就把字段 9 当 CustomEditor；`read_mzgui_tail()` 仅判断版本 `>4102`，并从末尾接受任意满足“剩余字段数等于 count”的数字。动态复现中，`UNRELATED_FIELD_9` 被覆盖成 `MZGUI.MZGUI`，`[..., FUTURE_SEMANTIC_FLAG, 0]` 被改成 `[..., FUTURE_SEMANTIC_FLAG, 1, [HelpBoxMzgui(#0041)]]`。
- 伪覆盖：`tests/test_custom_gui.py:145` 的“跨版本”用例只替换 `Version=19602` 文本，仍沿用完全相同的 1.9.6.2 合成字段布局；`tests/test_custom_gui.py:162` 只让最后字段变为非数字，无法覆盖未来格式以 `0` 结尾的歧义。
- 影响：直接违反 README/架构中“未知尾部失败关闭、不按版本号猜兼容”的承诺；在真实其他 ASE 版本上可能改变非目标字段、破坏图的可编辑性或让重编译生成错误 Inspector 元数据。真实未来 ASE 资产的损坏范围尚未实机验证，但误写机制已经成立。
- 最小修复方向：为每个真实采证的 ASE 图版本建立精确 schema/signature；CustomEditor 字段和 MZGUI 尾部必须分别命中已知布局与完整结构约束。未知版本只允许只读解析，任何语义写入均拒绝。
- 关联优化任务：AA-OPT-002。

### [P2] AA-FAIL-001 — 失败清理只能由可证明身份的 Editor 事务执行 — `src/asecli/cli/create_command.py:105`

- 证据等级：已验证。
- 触发条件：Editor 已创建目标，但 Python 后验解析/结构验证失败；在 RPC 返回后，另一进程原位修改或替换同一路径资产或 `.meta`。
- 错误行为：`_cleanup_failed_editor_create()` 的注释声称只删除本次 absent-before-call 产物，但实现只按路径对目标和 `.meta` 调用 `unlink()`，没有 nonce、digest、inode 或事务所有权校验。临时目录复现中，把 Editor 产物替换为 `replacement from another process` 后调用清理，替换文件仍被删除。
- 影响：低概率竞态可升级为用户数据丢失；错误路径的“保持目录干净”不能优先于“不删非本事务文件”。
- 最小修复方向：由 Editor 端使用事务 nonce 管理暂存与回滚，Python 不再对 RPC 后的路径做无条件删除；若保留后验清理，必须在创建结果中返回并校验不可伪混的资产身份，身份变化时保留文件并报告人工处理。
- 关联优化任务：AA-OPT-003。

### [P2] AA-PROTO-001 — 只接受与当前请求 ID 精确匹配的 SSE 响应 — `src/asecli/bridge/mcp_client.py:102`

- 证据等级：已验证。
- 触发条件：一次 SSE 响应体包含多个带 `id` 的 JSON-RPC frame，当前请求 frame 后还出现陈旧或无关 frame。
- 错误行为：注释声称优先当前请求 ID，实际倒序返回任意带 `id` 的 frame；`_rpc()` 也不复核响应 ID。mock 中当前请求 ID 为 `1`，响应依次含 `id=1/current` 与 `id=999/stale-later`，客户端最终返回 `id=999`。
- 影响：recompile/create 可能把其他操作的成功、失败或结果当作当前调用，破坏“请求—结果—资产”对账；显式允许远程 MCP 时影响面更大。
- 最小修复方向：把 payload ID 传入 SSE 解析，只返回精确匹配 frame；缺失、重复或不匹配时以稳定协议错误失败。普通 JSON 响应也执行相同 ID 校验。
- 关联优化任务：AA-OPT-004。

### [P3] AA-COMPAT-001 — 原生 GUI 检测无法确定时不得宣称缺失 — `src/asecli/bridge/gui_support.py:22`

- 证据等级：已验证。
- 触发条件：合法源码使用 `class MZGUI : UnityEditor.ShaderGUI`（或 `global::UnityEditor.ShaderGUI`），而不是先 `using UnityEditor` 后写裸 `ShaderGUI`。
- 错误行为：检测正则只接受裸 `ShaderGUI`。临时 Unity 项目含 `namespace MZGUI { public class MZGUI : UnityEditor.ShaderGUI {} }` 时，结果仍为 `detected=false`、`provider=missing`、`would_write=true`。预编译 DLL 还只依赖文件名含 `mzgui`，存在同类静态盲区。
- 影响：工具违反“原生 MZGUI 优先且存在时不安装”的承诺，可能写入第二套 GUI 资源并推荐较窄的兼容 Inspector；不会直接覆盖原生文件，因此定为 P3。
- 最小修复方向：源码检测至少覆盖全限定/global 基类；对预编译程序集使用 Unity 运行时反射做最终确认。静态结果不确定时返回 `unknown`，写入需显式确认或 Editor 检测证据。
- 关联优化任务：AA-OPT-005。
