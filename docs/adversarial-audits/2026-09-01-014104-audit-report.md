## Findings 详情

### [P1] AA-COR-001 — CRLF 文件解析直接崩溃 — core/model.py:AseFile.from_text

- 证据等级：已验证（复现脚本：LF→CRLF 转换后 `from_text` 抛 `ValueError: first graph line must be Version=...`）
- 触发条件：文件使用 `\r\n` 行尾（Windows 编辑/保存的 shader，团队协作常见）
- 错误行为：`from_text` 在 BEGIN 标记后只识别 `\n`；CRLF 时 body 首行为空串，`parse_graph_text` 直接抛异常——整个文件完全不可用，而非降级
- 影响：Windows 侧保存的 shader 全部无法读取；agent 路径在此类文件上必失败
- 最小修复方向：识别 `\r\n`/`\n` 两种行尾，解析后按原始行尾序列化（checksum 才能一致）
- 关联优化任务：AA-OPT-001

### [P1] AA-COR-002 — 图内空行被静默丢弃 — core/model.py:parse_graph_text

- 证据等级：已验证（图尾加一空行后 `serialize() != 原文`）
- 触发条件：ASEBEGIN 块内任何位置出现空行（ASE 某些版本/手工编辑会写入）
- 错误行为：`parse` 跳过空行 → 序列化丢字节 → roundtrip 破坏；`validate` 基于重建文本计算 CHKSM 产生**误报** CHECKSUM_MISMATCH
- 影响：静默改变用户文件字节；校验器可信度下降
- 最小修复方向：空行作为指令保序保留
- 关联优化任务：AA-OPT-002

### [P1] AA-COR-003 — rename 不彻底导致重编译回退旧名 — cli/main.py:cmd_create

- 证据等级：已验证（`Shader "HLIT"` 声明外，Master 节点行内仍含 `HLIT` 字段）
- 触发条件：`create --name New` 后执行 `recompile`
- 错误行为：ASE 从 Master 节点图数据重新生成 `Shader "HLIT"`，声明被改回旧名——用户以为创建了 New，编译后变回 HLIT
- 影响：静默数据回退，违背"创建"语义
- 最小修复方向：rename 时同步替换节点行内以分号定界的旧名字段
- 关联优化任务：AA-OPT-003

### [P2] AA-OPS-004 — 非原子写且无备份 — cli/main.py:_save / cmd_fix_checksum / cmd_create

- 证据等级：已验证（代码路径：`Path.write_text` 直写目标）
- 触发条件：写盘过程中进程被杀/磁盘满/编辑器同时写同一文件
- 错误行为：目标 shader 处于半写状态，原内容丢失
- 影响：用户真实资产损坏且不可恢复；agent 批量操作放大概率
- 最小修复方向：临时文件 + `os.replace` 原子替换；覆盖前写 `.bak` 备份
- 关联优化任务：AA-OPT-004

### [P2] AA-COR-005 — add-node 复用占位 guid/ID 字段 — core/graph_ops.py:node_from_schema

- 证据等级：高置信推断（schema 由 id=999 占位实例提取，字段中的 32 位 hex 串随模板复制）
- 触发条件：`add-node` 添加带内嵌 guid/唯一 ID 字段的节点类型（属性类、函数引用类）
- 错误行为：同一文件内多个新节点携带相同 guid → ASE 内部注册冲突或引用错乱
- 影响：图在 Unity 中行为不可预期
- 最小修复方向：插入时检测 32 位 hex 字段并告警（完整重建 guid 属后续功能）
- 关联优化任务：AA-OPT-005

### [P2] AA-TST-006 — 桥接端到端未验证 — tests/test_bridge_recompile.py

- 证据等级：未验证假设（MCP 会话被另一进程占用，execute_code 无响应）
- 触发条件：验收执行 REG-0005/0006
- 错误行为：未知——`SaveToDisk` 对 CLI 创建文件的再生产行为未观察
- 影响：发布声明"可编译"缺乏证据
- 最小修复方向：MCP 空闲后执行 `pytest -m bridge` 并归档证据
- 关联优化任务：AA-OPT-006

### [P3] AA-OPS-007 — recompile 泄漏隐藏窗口实例 — bridge/recompile.py:RECOMPILE_SNIPPET

- 证据等级：已验证（代码路径：CreateInstance 后无 Destroy）
- 触发条件：每次 recompile
- 错误行为：编辑器内存中累积隐藏 ASE 窗口
- 影响：长期会话内存增长；UIUtils 静态状态被最后一次实例占据
- 最小修复方向：finally 中 `UnityEngine.Object.DestroyImmediate(win)`
- 关联优化任务：AA-OPT-007

### [P3] AA-OPS-008 — SSE 响应只取首个 data 行 — bridge/mcp_client.py:_post

- 证据等级：高置信推断
- 触发条件：服务器以多条 SSE 事件返回（长任务进度 + 最终结果）
- 错误行为：可能读到中间帧，丢最终结果
- 影响：长任务结果解析不稳
- 最小修复方向：收集全部 data 行，取含响应 id 的最后一条
- 关联优化任务：AA-OPT-007
