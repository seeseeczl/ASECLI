## 审计边界

- 范围：用户提供的正常阅读缩放 ASE 节点图截图；可见 Comment 分区包括“基础颜色、拉花与环境反射”“清漆层”“清漆 LTC”“法线贴图”“环境遮蔽 AO”“金属度”“光滑度”“发光与世界空间假高光”和“基础发光 + 假高光 + 清漆 Cube/LTC 区域光”。
- 方法：仅截图的只读视觉对抗审查；以读者在改动端口、定位跨模块依赖、对照重复算法分支时最容易误判的路径为攻击面。未读取 `.shader`、节点 ID、WireConnection 或实时 TruePosition，也未打开或操作真实 ASE 画布。
- 输入材料：`codex-clipboard-c6982138-fbb0-41be-ad28-50814f87a42f.png`。
- 威胁假设：后续维护者在正常缩放下只根据画布修改一个输入、复制一条分支或追踪一个最终材质通道；错误连到近邻端口、漏掉跨模块依赖或在错误模块复用中间结果，都会造成难以即时定位的渲染回归。

## 威胁与失败模型

- 资产：车漆、清漆、LTC、法线、AO、金属度、光滑度、发光与假高光的正确数据依赖，以及安全维护这些依赖的画布可读性。
- 攻击者能力：不改变节点类型或公式，只移动/新增一个节点、替换一个输入、或按视觉猜测跨块来源；这正是图形编辑中的常见人为失误。
- 最贵失败：清漆或基础光照数据接错但 Shader 仍能编译，直到特定材质、灯光或视角出现反射/高光错误才暴露。

## 目标排版模型（用户确认）

- 采用横向鱼骨/脑图结构，而不是把模块压成若干孤立矩形：最左为输入与参数，向右依次是采样/解码、局部计算、层级合成、最终输出。
- 每一个语义层级使用固定的 x 列；同一层级的节点、并行 Comment 出口和重复分支节点必须垂直对齐。
- 一条功能主链是一根水平“骨干”；辅助输入只在其上/下展开，先短距离汇入所属骨干，不能以斜向长线跳过多个层级。
- 并行材质层（基础色、清漆、LTC、发光等）使用上下分叉、同列推进、右侧收束的脑图层次；全图只保留必要的空白走线通道。

## Findings 详情

### [P1] AA-LAYOUT-001 — 消除跨越多个语义区的长距离数据线 — 画布中央橙色线

- 证据等级：已验证（视觉）。截图中一条橙色线从左侧“基础颜色、拉花与环境反射”分区的下部横跨大段空白，进入“清漆层”下方区域；它不属于相邻、单次消费的局部连线。
- 触发条件：维护者在基础色或清漆输入处新增、替换或断开节点，或需要判断该橙线的来源、端口和消费语义。
- 错误行为：长线把两个 Comment 模块的边界变成“视觉上分开、依赖上强耦合”。在正常缩放下，线的两端和中间经过的模块无法一次同时清晰读取，极易将它误当成背景线或连接至相邻端口。
- 影响：Shader 通常不会因错线而报错，错误会延迟为特定角度/材质下的清漆、颜色或光照表现回归；这是高成本、低可见度的人为接线风险。
- 最小修复方向：若该值被清漆区或其他远端模块消费，生产侧右缘放置一个语义明确的 `Register Local Var`，消费区左缘放置 `Get Local Var`；若仅一次消费，则将生产者与消费者编入相邻阶段列并保留空白走线通道。不得改变端口、计算或重复计算。
- 关联优化任务：AA-OPT-001。

### [P1] AA-LAYOUT-002 — 为最终合成建立横向鱼骨主干 — 全图宏观布局

- 证据等级：高置信推断。截图上方是基础色/清漆/LTC 三个大块，中部是法线、AO、金属度、光滑度，下方左侧又出现很大的“发光与世界空间假高光”块，右下才是一个小型“基础发光 + 假高光 + 清漆 Cube/LTC 区域光”块；截图内未能在正常缩放下直接辨认一个从这些阶段连续收束到 Master 的单向主干。
- 触发条件：新增一个最终材质通道、追踪 Base Color/Normal/Metallic/Smoothness/Emission 中任一输出，或审查是否有反向依赖。
- 错误行为：阅读顺序被分割成“上排大块 → 中部散点 → 左下大块 → 右下小块”，维护者必须在大面积留白之间寻找收束点，而不是沿稳定的水平骨干、固定列和上下分叉推进。若 Master 位于截图外或被局部块遮蔽，风险进一步增加。
- 影响：对最终输出的追踪成本高，增加把补丁接到中间局部 Combine 而非最终消费者的概率；该类错误能编译但会造成某个渲染通道静默失效。
- 最小修复方向：先从 Master 输入反向列出每一条最终通道；把输入、采样/解码、材质层计算、合成和 Master 固定为连续阶段列。每个功能块设一条水平骨干，分支只在骨干上/下展开；模块出口统一朝右并对准同一合成列。不得为了紧凑而改变数据依赖。
- 关联优化任务：AA-OPT-002。

### [P2] AA-LAYOUT-003 — 把清漆 LTC 的重复上/下分支做成可对照模板 — “清漆 LTC”Comment

- 证据等级：已验证（视觉）。该 Comment 内上、下两组紫色/蓝色链路明显具有平行结构，但左侧输入栈、混合节点和右侧汇合点的列、行距与上下对应关系不够一眼可比；多条曲线在狭窄区域并行汇入。
- 触发条件：只修改其中一支（例如针对一个 LTC 方向、层或条件）的参数/端口，或需要检查上下支是否使用同样的处理序列。
- 错误行为：维护者不能在一次扫视中确认“第 N 行对应第 N 行、同一列是同一阶段”，容易只修改一支或把另一支的输入当作同一语义。
- 影响：上下分支逐渐漂移后，材质行为不对称且 review 难以发现；密集汇线还会掩盖端口错接。
- 最小修复方向：识别确实重复的两条链，使用完全相同的阶段 x 坐标、节点顺序、行距和 Comment 内边距；只在有真实语义差异的位置保留不同节点或注释。汇合节点保持最右列，输入各自在左列就近进入。
- 关联优化任务：AA-OPT-003。

### [P2] AA-LAYOUT-004 — 用横向层级列收敛离散小分区和无效留白 — 中部与下部模块区

- 证据等级：已验证（视觉）。法线/AO/金属度/光滑度四个小分区呈两行两列排列，但左边界、宽度、上下间距和标题对齐不一致；下方大“发光”块与右下合成块之间留有远大于走线通道所需的空白。
- 触发条件：新增或复制一个表面响应模块，或在正常缩放下尝试快速比较四条独立材质通道。
- 错误行为：小模块缺少共同的模块网格，空白既未服务于长线通道，也没有形成清晰阶段边界；后续节点很可能填入随机位置，导致宏观布局继续退化。
- 影响：维护者难以判断这些块是并行输入、先后阶段还是遗留计算，增加错误复用和重复计算的概率。
- 最小修复方向：为同类表面通道建立统一的阶段 x 列、水平骨干 y 基线、上下分支行距和 Comment 左/右边界；而非追求相同矩形尺寸。仅保留真正承载跨模块连线的空白通道。移动 Comment 时连同成员作为复合单元。
- 关联优化任务：AA-OPT-004。

## 测试与观测缺口

- 缺失用例：对当前 `.shader` 执行 `asecli parse`、`validate`、`graph-audit`，不能从截图确认是否存在悬空线、跨组复用、未使用节点或外部消费者。
- 缺失画布证据：截图不能显示所有节点的真实 `TruePosition`、端口锚点和贝塞尔曲线；本次按用户要求不读取或打开真实 ASE 画布，因此这些项保持未验证。
- 缺失语义证明：无法仅凭颜色和布局确认橙色长线的值语义、是否多消费者，以及 LTC 上下分支是否应当严格同构。

## 残留风险

- 未覆盖区域：截图外 Master 位置、所有连接 ID、实际编译结果、材质球画面与目标团结版本。
- 为何还不能安心发布：本审计证明的是当前画布存在高风险可维护性路径，不证明连接已错误；任何整理必须保持语义不变，并以 `validate`、recompile 和真实材质回归验收为前提。
