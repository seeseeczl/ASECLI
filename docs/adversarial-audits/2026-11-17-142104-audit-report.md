## Findings 详情

### [P0] AA-DATA-001 — 全局回退路径会把命令发往其它工程的编辑器 — `codely_discovery.py:registry_candidates`
- **证据等级**：已验证
- **触发条件**：目标工程内**没有** `.com-unity-codely.json`（新建工程、未装 Codely 的工程、注册文件被删），但 `~/.unity-tcp/unity-tcp-port.json` 存在（本机就存在）
- **错误行为**：`read_port_registry` 依次尝试工程内 → 工程内旧名 → `$HOME/.unity-tcp/`。命中 home 级文件后**直接返回其中的 `unity_port`**，完全不校验该端口属于哪个工程
- **复现**：
  ```
  candidates: ['/tmp/xxx/.com-unity-codely.json',
               '/tmp/xxx/unity-tcp-port.json',
               '/Users/long/.unity-tcp/unity-tcp-port.json']
  read result: {'unity_port': 53996, 'project_path': '/Users/long/Tuanjie3D/P376/Assets', ...}
  ```
  在一个空工程目录读到的是 **P376** 的端口
- **影响**：ASECLI 对工程 A 执行 `create`/`recompile`/`layout --write` 时，指令落到工程 B 的编辑器。工程 B 的 ASE 图会被当作工程 A 的资产操作；CLI 还会报告成功（因为编辑器确实执行了）。这是跨工程数据损坏
- **最小修复方向**：删除 home 级回退；或保留但对 `project_path` 做严格前缀校验，不匹配即视为未发现
- **关联优化任务**：AA-OPT-001

### [P1] AA-DATA-002 — 注册文件 `project_path` / `reloading` 从不校验 — `codely_discovery.py:read_port_registry`
- **证据等级**：已验证
- **触发条件**：工程内注册文件存在，但 `project_path` 指向别的工程，或 `reloading: true`
- **错误行为**：只校验 `unity_port` 是 int；`project_path`、`reason`、`last_heartbeat`、`reloading` 全部忽略
- **复现**：
  ```
  accepted despite different project_path: /some/OTHER/project/Assets
  reloading=True accepted: True
  ```
- **影响**：(a) 工程被复制/移动后注册文件未更新 → 操作错工程；(b) 编辑器正处于程序集重载时连接，脚本必然失败，但 ASECLI 不区分"重载中"与"真失败"
- **最小修复方向**：校验 `project_path` 与目标工程的 `Assets` 目录一致；`reloading: true` 时给出明确可重试提示
- **关联优化任务**：AA-OPT-001

### [P1] AA-SEC-004 — 握手/读帧超时路径泄漏 socket — `codely_client.py:_read_handshake / _recv_exactly`
- **证据等级**：已验证
- **触发条件**：TCP 连接建立成功，但服务端握手超时或响应体读取超时
- **错误行为**：`socket.timeout` 是 `OSError` 子类，但 `_read_handshake` 与 `_roundtrip` 的 `except` 分支**没有关闭 socket**。`_read_handshake` 仅在握手串不匹配时调用 `close()`
- **复现**：
  ```
  timeout path: CodelyError after 5.0s
  sock: <socket.socket fd=4, ... laddr=('127.0.0.1', 64446)>
  ---
  CodelyError after 2.0s: timed out after 2s
  sock still open: True
  ```
- **影响**：每次失败泄漏一个 fd。长时间运行的 Agent 会话反复探测/失败会耗尽 fd，最终整进程不可用
- **最小修复方向**：`connect()` 在握手异常时强制 `close()`；`_roundtrip` 的异常分支同样关闭
- **关联优化任务**：AA-OPT-003

### [P1] AA-UX-005 — Codely 错误被归类为 `INTERNAL`，用户无法诊断 — `cli/commands.py` 等调用点
- **证据等级**：已验证
- **触发条件**：Codely 后端执行失败（脚本报错、连接失败、握手不匹配）
- **错误行为**：CLI 各命令只捕获 `McpError`；`CodelyError`/`BackendError` 落到兜底 `except Exception`，输出 `{"code":"INTERNAL"}`
- **复现**：
  ```
  {"ok":false,"error":{"code":"INTERNAL",
   "message":"CodelyError: Codely script did not return a result:
              C# script execution failed: shader not found: Assets/T.shader"}}
  ```
- **影响**：用户看到"内部错误"而非"桥不可用/脚本失败"，无法自行排查；Agent 也无法据此选择重试或降级
- **最小修复方向**：在 CLI 层把 `CodelyError`/`BackendError` 映射为 `BRIDGE_ERROR`，与 MCP 路径一致
- **关联优化任务**：AA-OPT-002

### [P2] AA-LOGIC-006 — 握手超时不遵循调用方 timeout — `codely_client.py:_recv_until`
- **证据等级**：已验证
- **触发条件**：调用 `probe(..., timeout=1)` 且服务端握手迟滞
- **错误行为**：`_recv_until` 写死 `WELCOME_TIMEOUT=10.0`，忽略实例 `self.timeout`
- **复现**：`caller timeout=1s, actual=10.0s, ok=False`
- **影响**：`auto` 模式每次探测可能隐藏 10 秒延迟；配合 AA-SEC-004 还会泄漏 socket
- **最小修复方向**：使用 `min(WELCOME_TIMEOUT, self.timeout)`
- **关联优化任务**：AA-OPT-003

### [P2] AA-LOGIC-007 — `auto` + `unity_instance` 直接失败而不回退 MCP — `backend.py:run_code`
- **证据等级**：已验证
- **触发条件**：`--editor-backend auto` 且传 `--unity-instance`（多编辑器场景）
- **错误行为**：`auto` 先选中 Codely，随后 `run_code` 因 Codely 不支持 `unity_instance` 抛 `BackendError`，**不回退**到支持该参数的 MCP
- **复现**：
  ```
  BackendError: unity_instance is not supported by the codely backend;
  Codely addresses the editor that owns the project's port registry
  ```
- **影响**：多编辑器用户从 MCP 迁移到 `auto` 后功能直接不可用，属于回归
- **最小修复方向**：`auto` 时若存在 `unity_instance` 则跳过 Codely 直接选 MCP
- **关联优化任务**：AA-OPT-004

### [P2] AA-DATA-008 — `extract_payload` 静默返回整个信封 — `editor_result.py:extract_payload`
- **证据等级**：已验证
- **触发条件**：`data.result` 存在但为空字符串、或不是字符串
- **错误行为**：拿不到 payload 时 `return text`，把**整个 JSON 信封**当结果返回
- **复现**：
  ```
  empty result str: '{"success": true, "data": {"result": ""}}'
  result not str:   '{"success": true, "data": {"result": {"a": 1}}}'
  ```
- **影响**：上层 `_parse_result` 找不到协议标记，报"结果缺少协议标记"，掩盖真实原因；若内容恰好含标记还可能误解析
- **最小修复方向**：`data` 存在但无可识别字符串 payload 时抛 `EditorExecutionError`
- **关联优化任务**：AA-OPT-005

### [P3] AA-LOGIC-009 — 探测只验证 trivial 脚本 — `codely_client.py:probe`
- **证据等级**：已验证
- **触发条件**：Codely 可用但 ASE 未加载 / ASE 版本不兼容
- **错误行为**：探测只执行 `return "asecli-probe-ok";`，通过即认为后端可用
- **影响**：真正的 ASE 能力缺失要到业务调用时才暴露，且错误信息不指向根因
- **最小修复方向**：探测可选地验证 ASE 类型存在（`AmplifyShaderEditorWindow`）
- **关联优化任务**：AA-OPT-006

## 测试与观测缺口
