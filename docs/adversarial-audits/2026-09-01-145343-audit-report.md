## 4. Findings 详情

### [P1] AA-COR-009 — `layout` 破坏 Commentary 与 Local Var 编排

- 代码路径：`src/asecli/core/layout.py:19-127`、`src/asecli/cli/commands.py:193-197`。
- 触发条件：对已经按“自定义 GUI + Comment 分组 + Local Var 复用”规范整理的图执行 `layout --write`。
- 根因：布局器只把显式 `WireConnection` 当作边，并把 CommentaryNode、RegisterLocalVarNode、GetLocalVarNode 与普通计算节点一起独立排布；Comment 成员关系和 Get→Register 隐式引用均未进入布局模型。
- 动态证据：真实图临时副本执行后返回 `ok=true`、`moved=303`。执行前 25/25 个 Comment 的成员节点原点均位于各自框内；执行后 25/25 个 Comment 均失效，共 250 个成员原点跑出所属框。
- 影响：工具会主动摧毁用户要求的算法分区、提示说明和复用治理，形成更严重的蜘蛛网节点视图；命令仍报告成功。
- 修复方向：在语义布局完成前，检测到 Comment 或 Local Var 时默认拒绝写入；最终实现以 Comment 为复合布局单元、以 Get→Register 为语义边的布局器。

### [P1] AA-COR-010 — Local Var 悬空引用未被结构校验发现

- 代码路径：`src/asecli/checks/validate.py:9-116`、`src/asecli/core/graph_ops.py:8-38`。
- 触发条件：`set-field` 修改 GetLocalVarNode 的 Register 引用字段，或删除仍被 Get 引用的 RegisterLocalVarNode。
- 根因：校验器覆盖节点 ID、显式 Wire 与 Commentary 成员关系，但完全没有解析 Local Var 的隐式引用。
- 动态证据：把 Get 节点 `1212` 的字段 6 从真实 Register ID 改为不存在的 `999999`，`set-field --write` 返回成功；随后 `validate` 仍返回 `ok=true`、`error_count=0`，只有非阻断 CHECKSUM warning。
- 影响：Agent 可生成 ASE 中不可解析或含错误算法引用的图，同时把验证结果当成结构正确；新 Skill 鼓励复用 Local Var 后，触发面显著扩大。
- 修复方向：建立 Register/Get 解析与校验，至少检查目标存在、目标类型、显示名/数据类型一致性、重复注册与引用环；删除被引用 Register 时必须阻断并返回引用者列表。

### [P1] AA-SEC-011 — 可预测临时与备份路径可被符号链接利用

- 代码路径：`src/asecli/cli/io.py:9-17`。
- 触发条件：不可信工作树预置 `target.shader.tmp` 或 `target.shader.bak` 符号链接，用户/Agent 对 `target.shader` 执行任一 `--write`。
- 根因：固定文件名配合 `Path.write_text/write_bytes` 会跟随符号链接；写入前未使用 `lstat`/`O_NOFOLLOW`，也未独占创建临时文件。
- 动态证据：令 `target.shader.tmp -> victim.txt` 后调用 `atomic_write`，`victim.txt` 被改成 `MUTATED`，最终 `target.shader` 也成为指向 victim 的符号链接；`.bak` 路径具有同类问题。
- 影响：在 CLI 进程权限范围内覆盖任意可写文件，属于本地工作树到宿主文件系统的边界突破。
- 修复方向：同目录安全唯一临时文件（`mkstemp`/`O_EXCL`）、拒绝符号链接目标与备份、写入并 `fsync` 后原子替换；加入恶意 symlink 回归。

### [P2] AA-COR-012 — 混合 EOL 无法字节级 roundtrip

- 代码路径：`src/asecli/core/model.py:91-95,98-124,160-192`。
- 触发条件：ASE 图块内部同时含 LF 与 CRLF，例如仅 `Version=19109` 行为 CRLF。
- 根因：解析器只保存一个全局 `graph.eol`；只要图内出现任一 CRLF，序列化就用 CRLF 重建整个图块。
- 动态证据：构造只有 1 个 CRLF 的真实 fixture，`AseFile.from_text(mixed).serialize() == mixed` 为 `false`；输出图块出现 11 个 CRLF。
- 影响：违反 `serialize()` 的“without mutations byte-identical”公开承诺，并让仅查询后再写的路径产生非业务字节漂移。
- 修复方向：逐行保留原始行尾；新插入指令采用邻近或显式策略。若不支持，应在写入前拒绝 mixed-EOL，而不是静默归一化。

### [P1] AA-OPS-013 — 并发写入发生静默丢失更新

- 代码路径：`src/asecli/cli/commands.py:40-55`、`src/asecli/cli/io.py:9-17`。
- 触发条件：两个 Agent/进程或 Agent 与 ASE 编辑器基于同一旧文件分别修改不同节点，随后先后写回。
- 根因：加载时不保存源版本指纹，提交时不比较目标当前哈希，也没有进程间锁；“原子替换”只保证单次写不半写，不保证不会覆盖更新。
- 动态证据：两个快照分别修改节点 0 与节点 1，按 A→B 写回且两次均无异常；最终节点 1 修改保留，节点 0 恢复原值，A 的合法修改被 B 静默覆盖。
- 影响：多 Agent 与编辑器协作时产生难以察觉的数据丢失；`.bak` 只能保留最近一版，后续写入还会继续覆盖备份。
- 修复方向：ASECLI 写者锁 + 加载指纹 + 锁内比较后提交；不一致返回明确 `WRITE_CONFLICT`，不得自动覆盖。另行记录不遵守锁的编辑器竞争残留风险。

### [P2] AA-COR-014 — `create --name` 注入和过宽替换

- 代码路径：`src/asecli/cli/commands.py:200-223`。
- 触发条件：名称包含 `"`、CR/LF 或控制字符；或图内其他分号字段恰好等于旧 Shader 名。
- 根因：只拒绝分号，随后直接插入 ShaderLab 声明；图内同步改名使用全文 `text.replace(f";{old};", ...)`，没有限定 Master 节点的名称字段。
- 动态证据：传入 `Bad"\nTHIS_IS_INJECTED\nShader "Nested` 返回 `ok=true`，输出出现 3 个 `Shader "` 声明；另一个有效模板中的无关 Comment 标题 `HLIT` 被创建命令改成 `BrandNew`。
- 影响：生成非法或被注入额外 ShaderLab 文本的文件，并静默篡改帮助说明/分组标题。
- 修复方向：严格校验名称字符集；仅通过解析后的 Master 节点语义字段更新图内名称；写出前重新解析并验证。

### [P1] AA-COR-015 — 第一个 `//CHKSM=` 可触发灾难性截断

- 代码路径：`src/asecli/checks/checksum.py:17-31`、`src/asecli/cli/commands.py:180-190,217-219`。
- 触发条件：Shader 源码、帮助注释或字符串在真正尾部校验和之前出现文本 `//CHKSM=`。
- 根因：`verify_checksum`、`fix_checksum` 与 `create` 均使用 `find` 选择第一个标记；`fix_checksum` 把从该位置到文件尾的所有内容替换为一个哈希。
- 动态证据：在真实 117,656 字节 fixture 的 Shader 壳中加入一行 `// decoy //CHKSM=NOT_THE_TRAILER`，执行 `fix-checksum --write` 返回 `ok=true`；输出只剩 180 字节，`ASEBEGIN` 整图消失。首次 `.bak` 保留原文，但命令未报告数据损坏。
- 影响：合法文本即可让修复命令破坏整个资产；自动化批处理会放大损失。
- 修复方向：只接受文件尾部、独占整行、格式合法的 checksum trailer；多标记或非尾部标记必须报错或按明确规则处理，绝不能截断图体。

### [P2] AA-OPS-016 — 重编译异常清理与静态窗口状态不完整

- 代码路径：`src/asecli/bridge/recompile.py:12-22`。
- 触发条件：`LoadObject` 或 `SaveToDisk` 抛异常；或成功后其他 ASE 操作读取 `UIUtils.CurrentWindow`。
- 根因：窗口创建后没有 `try/finally`；只在成功路径 `DestroyImmediate(win)`，且设置 `UIUtils.CurrentWindow = win` 后从不恢复先前窗口。成功路径结束后静态字段仍指向已销毁对象。
- 证据边界：静态控制流已确认；本轮没有连接真实 Unity/团结编辑器注入异常，因此编辑器侧表现未实测。
- 影响：失败重试可累积隐藏窗口；静态全局状态污染可能干扰用户当前 ASE 窗口或后续自动化。
- 修复方向：保存旧 `CurrentWindow`，在 `finally` 中恢复并销毁临时窗口；补代码契约测试与真实编辑器成功/异常验收。
