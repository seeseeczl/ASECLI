## Findings 详情

### [P1] AA-COR-001 — 必须用 `template.shader_name` 创建真实 Shader 声明 — `src/asecli/bridge/resources/editor_create.cs.txt:73`

- 证据等级：已验证。
- 触发条件：规格的 `template.shader_name` 与受控暂存文件名不同；这是正常情况。
- 错误行为：执行器读取 `shaderName` 后未使用，把 `ASECLI-Temp-*.shader` 文件名传给 `CreateNewTemplateShader`。隔离 E2E 实际生成 `Shader "ASECLI-Temp-e2e-caster"` 和 `Shader "ASECLI-Temp-e2e-receiver"`，而不是规格中的 `ASECLI/E2E/Caster`、`ASECLI/E2E/Receiver`。
- 影响：目标文件路径虽正确，Unity Shader 的公开名称错误；材质查找、迁移和自动验收会引用错误标识，当前 manifest 也无法发现漂移。
- 最小修复方向：将 `shaderName + ".shader"` 传入 ASE 创建接口；manifest 记录并回读校验模板 GUID 和真实 Shader 声明名；E2E 对最终 ShaderLab 声明做精确断言。
- 关联优化任务：AA-OPT-001。

### [P1] AA-COR-002 — 所有连接端口必须在调用 MCP 前完成白名单校验 — `src/asecli/bridge/_editor_spec_validation.py:164`

- 证据等级：已验证。
- 触发条件：白名单节点使用不存在的源/目标端口，例如源端口 `63`。
- 错误行为：Python 仅把端口限制在 `0..63`，只特别检查 Custom Expression 输入数量；错误端口规格能够完成解析并进入 MCP，直到真实 ASE 图查询才失败。
- 影响：违反“错误端口在 MCP 前失败”的接口约束，浪费编辑器调用并把可预测的规格错误变成环境相关失败；自动模式下也难以区分用户错误与 Editor 故障。
- 最小修复方向：建立 v1 白名单节点的输入/输出端口契约，校验端口存在性和源/目标基本类型兼容；模板 Master 仅开放已验证端口。
- 关联优化任务：AA-OPT-002。

### [P2] AA-DATA-001 — 同一规格内必须拒绝重复 Shader 属性名 — `src/asecli/bridge/_editor_spec_validation.py:60`

- 证据等级：已验证。
- 触发条件：两个 property/sampler 节点声明相同的 `property_name`，例如都为 `_GroundMask`。
- 错误行为：节点 alias 会去重，但 `property_name` 不会；该规格当前可被接受并送入 ASE。
- 影响：可能生成重复 Shader 属性或 uniform、发生 ASE 自动重命名，或保存/重载后 manifest 与请求语义不一致。
- 最小修复方向：在 Python 规格解析阶段对所有 property/sampler 的 `property_name` 做全局唯一性校验并补正反用例。
- 关联优化任务：AA-OPT-003。

### [P2] AA-FAIL-001 — 窗口关闭必须属于提交事务而不是成功后的清理 — `src/asecli/bridge/resources/editor_create.cs.txt:309`

- 证据等级：高置信推断。
- 触发条件：目标资产已 MoveAsset 提交，随后 `win.Close()` 或 `DestroyImmediate` 抛出异常。
- 错误行为：代码在进入 `finally` 前已设置 `success = true`；关闭异常会覆盖成功返回，但 `!success` 回滚分支不会执行，目标资产可能残留。
- 影响：调用方收到失败却观察到已写入目标，重试又因“目标已存在”失败；事务的失败不留目标承诺被破坏。
- 最小修复方向：在设置成功并返回前完成可失败的窗口关闭和状态恢复；关闭失败进入统一回滚。`finally` 只做不覆盖主异常的兜底清理。
- 关联优化任务：AA-OPT-004。
