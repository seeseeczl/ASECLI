## Findings 详情

### [P1] AA-COR-001 — 对图属性与编译区属性做双向一致性校验 — `src/asecli/core/custom_gui.py:210-239`

- 证据等级：已验证。
- 触发条件：文本创建使用一个 Shader 作为编译壳、另一个 Shader 作为 `--graph-from` donor；两者各自图内属性满足中文显示名和中文帮助，但属性集合不同。旧图版本或模板生成属性不表现为可识别 PropertyNode 时，也会形成空列表的真空通过。
- 错误行为：`inspect_custom_gui` 只从图版本 `19602` 的 PropertyNode 构造 `properties`，`inspect_property_presentation` 只遍历该列表。它不解析 ShaderLab `Properties`，不比较编译区与图内属性名、显示名和帮助元数据。空列表在 CustomEditor 一致时也会得到 `valid=true`。
- 动态证据：用真实 `VehicleLocalShadowCaster.shader` 作为 `--from`、真实 `VehicleLocalShadowReceiver.shader` 作为 `--graph-from` 执行文本创建，CLI 返回 exit 0 和 `valid=true`，报告 6 个合规图属性；输出文件的编译区却仍包含 `_CasterMask` 等 7 个仅编译区属性，图中 `_GroundMask`、`_PlaneY`、`_Strength` 等 6 个属性均不在编译区。
- 补充证据：`tests/test_create.py:26-38` 的 `compliant_shader()` 使用图版本 `19109` 的 `HLIT.shader`。该 fixture 的 `material_property_nodes()` 数量为 0，因此循环未执行，测试仍把包含英文 ShaderLab 属性的文件当成合规模板，形成假覆盖。
- 影响：直接违反“所有 CLI 创建结果都满足属性呈现规范”的成功条件；实际 Inspector 使用编译区属性，Tooltip/默认值/说明与图可能错位；创建结果需要重编译后才可能变化，不能在创建时宣称合规。
- 最小修复方向：增加编译区属性的安全解析和双向 reconciliation；正式创建至少要求公开编译属性与图内导出属性集合、显示名及 ASECLIHelpBox 一致。无法证明一致时失败关闭。文本 `--graph-from` 若属性契约不同，应拒绝并要求走真实 Editor 后端，而不是伪造编译属性。
- 关联优化任务：AA-OPT-001。

### [P1] AA-FAIL-002 — 检查器解析失败时不得返回“不适用” — `src/asecli/core/property_presentation.py:134-143`

- 证据等级：已验证。
- 触发条件：文件已经声明 ASECLI CustomEditor，但 `inspect_custom_gui` 因重复编译区 CustomEditor、未知布局或其他 `ValueError` 无法完成检查；随后调用 `set-field`、`layout` 等走通用 `_save` 的写命令。
- 错误行为：`require_managed_property_presentation` 捕获所有 `ValueError` 后直接返回 `None`，调用方把它当成无需执行契约并继续写盘。这与函数注释中的 fail closed 相反。
- 动态证据：复制当前合规 Receiver，加入第二条冲突 CustomEditor，然后执行 `set-field --node 23 --field 8 --value GroundMask --write`。CLI 返回 exit 0 且 `written=true`，图显示名被写为纯英文，文件仍含两条 CustomEditor。
- 影响：任意检查器错误都能把强制门禁降级成放行；损坏或新版本文件最需要保护时反而没有保护。现有“不能用通用 set-field 绕过”的测试只覆盖正常可检查输入。
- 最小修复方向：区分“已确认不是 ASECLI-managed”和“ASECLI 痕迹存在但检查失败”。只允许前者返回不适用；只要图或编译区能看到 ASECLI Editor/ASECLI 元数据，任何检查异常都应返回 `PROPERTY_PRESENTATION_ERROR`，并保证原文件 digest 不变。
- 关联优化任务：AA-OPT-002。

### [P2] AA-REL-003 — 发布新契约前升级包版本 — `pyproject.toml:3`

- 证据等级：已验证。
- 触发条件：从当前工作树构建并分发正式 CLI。
- 错误行为：`pyproject.toml` 与 `uv.lock` 仍为 `0.1.0`，本地已有 `v0.1.0` tag；但当前 CLI 已把正式 Editor 创建输入从 v1 改为 v2，并新增公开 JSON 字段和错误码。构建产物仍叫 `asecli-0.1.0-*`。
- 影响：安装器缓存、私有 Release 资产和用户环境无法可靠区分旧行为与新行为；同版本重发破坏可追溯与回滚。EditorGraphSpec v1 的 CLI 拒绝属于显著兼容变化。
- 最小修复方向：完成 P1 修复和真实 Editor 验证后，使用新的版本号发布；按当前兼容幅度建议 `0.2.0`，同步 lock、README/发布记录、tag、wheel/sdist 和哈希，不覆盖 `v0.1.0`。
- 关联优化任务：AA-OPT-003。
